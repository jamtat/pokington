## Outcome and scope

Design a Rust CLI with `choose`, `art`, and `bootstrap` commands. Implementation has not been requested or approved.

## Sources and current contract

- [Brief](brief.md) is the current requirements source. Accepted decisions below will clarify it; unresolved proposals are not requirements.
- The repository currently contains a Rust 2024 package with a placeholder `src/main.rs` and no declared dependencies. No application functionality exists to reuse.
- Required dependencies from the brief: `clap`, `reqwest`, and `ratatui-image`.
- Existing untracked `Cargo.lock` and `docs/brief.md` predate this design work and must be preserved.

## Requirements already specified

- Bootstrap from the official Pokémon website on first run; derive the catalogue size from source data.
- Store Pokédex number, name, primary and optional secondary type, and PNG artwork locally for repeated use.
- `choose` selects the requested count, excludes names case-insensitively and names occurring inside supplied files, prints one name per line, and reports impossible requests on stderr with exit status 1.
- `art` resolves a case-insensitive name or ID, chooses randomly when omitted, crops transparent margins, and supports image, Unicode block, and coloured ASCII output with suitable scaling.
- Automatic art mode prefers image output, then blocks, then ASCII according to terminal capability.
- Explicit bootstrap skips existing downloads; `--force` redownloads all assets. Bootstrap reports progress with a bar and a download log.

## Decisions

### D01 — Species names and artwork forms — 2026-11-06

- Options discussed: original forms only throughout, or alternate forms as separate catalogue entries. The accepted design separates species name selection from artwork form selection.
- User response: “For names only print the original pokemon names. For images we want alternate forms too. accept a --form argument for an explicit form. If no form specified assume original. When asking for random artwork also include all other forms as potential art selection”
- Accepted decision: keep one species entry per National Pokédex number for `choose`, using the original name. Associate original and alternate artwork forms with that species. `art <name/id>` selects the original form; `--form` selects an explicit form. With no Pokémon specified, random artwork includes originals and alternate forms.
- Rejected alternatives: originals-only artwork omits required forms; treating forms as additional name-selection entries violates original-name-only selection.
- Consequences: bootstrap must discover form identities and artwork URLs from the source. The numbered original-image URL pattern alone is insufficient. At acceptance, random sampling probabilities and form argument syntax remained unresolved; D02 subsequently settles probabilities.
- Contract updated: [Brief](brief.md).

### D02 — Random artwork distribution — 2026-11-06

- Options: A gives equal probability to every species/form artwork entry; B chooses a species uniformly, then a form uniformly.
- Recommendation: A matches selection of random artwork.
- User response: “A”
- Accepted decision: sample uniformly from the complete list of species/form artwork entries, including original forms.
- Rejected alternative: choosing species first changes the probability of individual artwork entries.
- Consequence: species with more forms have a greater combined probability. Eligibility is based on form entries, not the number of files or duplicate URLs stored locally.
- Contract updated: [Brief](brief.md).

### D03 — Descriptive form names and Mega Evolutions — 2026-11-06

- Recommendation: A is easier to remember, with invalid-form errors listing available form names.

### D07 — Explicit bootstrap refresh policy — 2026-11-06

- Options: A refreshes the catalogue on every explicit bootstrap and downloads new or missing artwork, with `--force` redownloading everything; B reuses the saved catalogue and discovers additions only with `--force`.
- Recommendation: A discovers additions without downloading existing artwork again.
- User response: “A”

With `--force`, also redownload existing artwork. After successful initial bootstrap, ordinary `choose` and `art` commands use local data without checking for updates.
- Rejected alternative: discovering catalogue additions only with `--force` needlessly couples metadata updates to full artwork downloads.
- Consequences: metadata refresh and artwork replacement are separate operations. Publication of refreshed metadata and recovery from failed downloads still require a storage design.

### D08 — Local JSON catalogue and PNG storage — 2026-11-06

- Options: A uses a versioned JSON catalogue and PNG files; B uses a SQLite catalogue and PNG files. Both use the platform's standard per-user application data directory.
- Recommendation: A suits the small catalogue and simple lookup needs, allows inspection, and avoids database code.

- Rejected alternative: SQLite adds query and transaction machinery without a current requirement for it.

### D09 — Bootstrap recovery and dataset publication — 2026-11-06

- User response: “y”

- Rejected alternative: publishing incomplete replacement data would make an existing installation depend on a failed update.

The exact staging and atomic publication mechanism is a bounded implementation design detail; successful downloads must remain reusable on retry.
- Contract updated: [Brief](brief.md).

### D12 — Automatic artwork with redirected stdout — 2026-11-06

- Options: A emits plain, uncoloured ASCII with no terminal control codes when stdout is piped or redirected; B fails and requires an explicit mode.
- Recommendation: A allows commands such as `art meowth > meowth.txt` to work naturally.

### D13 — Artwork colour control — 2026-11-06

- Proposal: `--color auto|always|never`, defaulting to `auto`, controls ANSI colour in block and ASCII rendering. `auto` uses colour in a terminal and plain text when redirected; `always` emits ANSI colour even when redirected; `never` renders monochrome text. Native image mode retains the PNG's colours. Redirected automatic mode still selects ASCII, with `always` able to colour it.
- User response: “y”
- Accepted decision: use the proposed colour interface and behavior.
- Rejected alternative: unconditional colour cannot provide both clean redirected text and an explicit coloured-output override.
- Consequences: keep output-mode selection separate from ANSI colour policy. Monochrome text renderers must preserve visible image structure without relying on colour. This option does not convert native PNG images to greyscale.
- Contract updated: [Brief](brief.md).

### D14 — Default sizing and original width option — 2026-11-06

- Options: A fits the terminal's width and height while preserving aspect ratio, with an 80-column default for redirected ASCII; B uses a fixed default of 80 columns everywhere. Explicit `--width n` sets the requested width in either case.
- Recommendation: A fits smaller terminals.
- User response: “A but add width `original` as a special case to always print original size”
- Accepted decision: use terminal fitting by default and 80 columns for redirected ASCII; accept an explicit numeric width or the special value `original` for original-size output.
- Rejected alternative: a fixed terminal width does not adapt to terminal dimensions.
- Consequences: numeric widths use character columns, but the original image is measured in pixels. Define original-size behavior for each renderer before implementation. Transparent-margin cropping remains required by the brief.
- Contract updated: [Brief](brief.md).

### D15 — Original-size rendering semantics — 2026-11-06

- Proposal: `original` disables resizing after trimming transparent margins. Native image mode uses one source pixel per screen pixel; blocks use one source pixel per half-block, packing two pixel rows per character row; ASCII uses one source pixel per character. Output may overflow the terminal and ASCII character proportions may stretch it vertically.
- User response: “y”
- Accepted decision: use the proposed original-size mappings and permit overflow. Cropping remains mandatory; original-size output is not fitted to terminal bounds.
- Rejected alternative: silently fitting original-size output would defeat the explicit override.
- Consequences: keep original-size rendering separate from normal aspect-correct scaling. Verify that selected native image protocols and the rendering library can preserve the required pixel sizing; character-cell dimensions alone cannot establish 1:1 native pixels.
- Contract updated: [Brief](brief.md).
