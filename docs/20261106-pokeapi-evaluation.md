# PokéAPI feasibility evaluation — 2026-11-06

Status: evaluation only; **PokéAPI has not been selected and has not passed every requirement**. Serebii remains the selected provider under D25 pending the user's source decision. This audit verifies the complete API metadata universe and representative assets, identifies concrete PNG gaps, and leaves full asset validation and canonical-form scope unresolved. It does not implement bootstrap, storage, offline operation or rendering.

## Source and traversal

Primary API documentation: [PokéAPI v2](https://pokeapi.co/docs/v2). The service documents GET-only consumption, no authentication, pagination with `limit`/`offset`, and local caching. This audit uses the already approved wreq Chrome147/macOS browser profile, four concurrent GETs and a persistent temporary response cache. It does not use browser control, imported credentials, summon, proxies or challenge solving.

Seeds: [species list](https://pokeapi.co/api/v2/pokemon-species/?limit=200), [Pokémon list](https://pokeapi.co/api/v2/pokemon/?limit=200), [form list](https://pokeapi.co/api/v2/pokemon-form/?limit=200). The runner follows returned URLs; it does not enumerate numeric IDs or construct artwork suffixes. Each detail body is bounded to 16 MiB. It rejects invalid JSON, foreign resource URLs, pagination loops, duplicate list names/URLs, inconsistent counts, incomplete pagination and listing/detail identity mismatches.

Cache: `/private/tmp/pokington-pokeapi/`. There are 3,955 metadata bodies totalling 224,500,351 bytes. Four recent parent-agent live probe bodies were reused (Dragonite/Charizard species, Unown Pokémon and Mega Dragonite Pokémon); the other 3,951 detail bodies were fetched in this traversal. Cache-file write times span 23:33:09–23:34:36 UTC; copied probe files' write times are not their original HTTP capture times. Cached list pages are reused too. The sorted filename/body-SHA-256 manifest has SHA-256 `855b1613b6486dd4ed829c67e88ddc317866fea00436d41f21db5ebd0df1db92` at `metadata-manifest.sha256`. Raw temporary captures are not durable repository fixtures.

Machine-readable outputs: `form-audit.json`, `summary.json`, `gap-forms.json`, `relative-keys.json`, `pokemondb-mega-comparison.json`, and `images/results.json` in that directory. The metadata runner's zero exit means it completed the audit, not that the provider passed every product requirement; its summary retains source anomalies and rejected short-label candidates.

## Naming, types and upstream inconsistencies

- English localized short form names alone collide ten times, including multiple Meteor Forms, Darmanitan Zen modes, Zygarde 10% forms, Urshifu/Toxtricity Gigantamax forms and Mega Meowstic. The accepted evaluation candidate uses the source's full form slug relative to its actual species slug, not numeric IDs or invented suffixes. Keys such as `galar zen`, `rapid strike gmax` and `low key gmax` preserve necessary distinctions. There are no collisions under this rule. This demonstrates a feasible naming mechanism; final CLI normalization/help behavior is not implemented.
- Original selection is a stored reference, not a reserved literal `original` key. Magearna's default form has key `default`; its actual Original Color variant has key `original`. Unown's original reference points to source form A (`a`). `mega x` is shared across applicable species, preserving cross-species form filtering.
- Eight alternative Pokémon varieties have zero forms flagged `is_default`: Koraidon Limited, Sprinting, Swimming and Gliding builds; Miraidon Low Power, Drive, Aquatic and Glide modes. Their form relationships are present. This contradicts the API's documented per-Pokémon default-form invariant, but does **not** make the required species original ambiguous; neither is the species' default variety. The audit records the discrepancy instead of inventing an extra product requirement or altering the source.
- The API has 28 Unown forms, 64 Alcremie forms (63 cosmetic combinations plus Gigantamax), 19 Arceus forms (including `arceus-unknown`), 18 Silvally forms, 14 Minior forms, 97 forms flagged Mega, and 34 forms with `gmax` in their source names. These are observed API resource categories, not a blanket claim that each is a canonical visibly distinct form.
- The `arceus-unknown` record explicitly has type `unknown`; this yields 19 distinct type strings in the complete audit. Its HOME and battle-sprite PNG URLs are declared but were not fetched in the 20-image sample. Whether to retain historical/unused records needs an explicit scope rule; no record was silently dropped or patched.
- Required examples are present with explicit ordered types: Charizard Mega X (Fire/Dragon), Mega Y and Gigantamax (Fire/Flying); Alolan Meowth (Dark), Galarian Meowth (Steel); Tauros Combat (Fighting), Blaze (Fighting/Fire), Aqua (Fighting/Water); Mega Dragonite (Dragon/Flying); newest Raichu Mega X/Y, Meowstic Mega male/female, Magearna Mega/Original Mega, and three Tatsugiri Mega forms. Arceus Bug remains Bug and Silvally Fighting remains Fighting rather than inheriting Normal from the parent resource.

## Exact PNG gaps

The following 44 resource names are directly present in the API's form list and form bodies. The absence of PNG URLs is verified across every nested sprite field. Their inclusion in the API does not itself settle whether all are separately renderable canonical forms; calling the Mothim/Scatterbug/Spewpa entries “internal states” or visually identical would require additional evidence or an explicit product rule. No such classification was silently used to exclude them.

- Mothim (2): `mothim-sandy`, `mothim-trash`.
- Scatterbug (19): `scatterbug-polar`, `scatterbug-tundra`, `scatterbug-continental`, `scatterbug-garden`, `scatterbug-elegant`, `scatterbug-meadow`, `scatterbug-modern`, `scatterbug-marine`, `scatterbug-archipelago`, `scatterbug-high-plains`, `scatterbug-sandstorm`, `scatterbug-river`, `scatterbug-monsoon`, `scatterbug-savanna`, `scatterbug-sun`, `scatterbug-ocean`, `scatterbug-jungle`, `scatterbug-fancy`, `scatterbug-poke-ball`.
- Spewpa (19): `spewpa-polar`, `spewpa-tundra`, `spewpa-continental`, `spewpa-garden`, `spewpa-elegant`, `spewpa-meadow`, `spewpa-modern`, `spewpa-marine`, `spewpa-archipelago`, `spewpa-high-plains`, `spewpa-sandstorm`, `spewpa-river`, `spewpa-monsoon`, `spewpa-savanna`, `spewpa-sun`, `spewpa-ocean`, `spewpa-jungle`, `spewpa-fancy`, `spewpa-poke-ball`.
- Koraidon/Miraidon modes (4): `koraidon-limited-build`, `koraidon-swimming-build`, `miraidon-low-power-mode`, `miraidon-aquatic-mode`.

The first 40 have declared non-PNG GIF and/or WebP references; those files were not fetched or converted. The last four have no sprite URL at all. This is already a concrete failure of a strict “one source PNG for every API form resource” contract. It does not prove that every missing resource is required by the final canonical-visible-form policy, nor that a different source lacks those depictions. Broader fetching stopped at this gap; no unbounded fallback hunt was performed.

## Freshness comparison

The preserved [Pokémon Database all-Pokémon table](https://pokemondb.net/pokedex/all) contains 1,261 rows and 93 Mega-labelled entries. Comparison used National species identity plus case/punctuation-insensitive name tokens; 92 matched API form names or English full names, and all matched type sets. Its undifferentiated “Mega Tatsugiri” row corresponds at the species/transform level to three explicit API forms, all Dragon/Water; it was not silently counted as an exact one-to-one identity match. This bounded cross-source check supports current Mega coverage but is not a global proof of every canonical form.

The preserved Serebii hub inventory has 96 labels beginning “Mega”. Four do not token-match API names: “Mega Kyogre”, “Mega Groudon”, “Mega Necrozma” and “Mega Tatsugiri”. API records use Primal Kyogre/Groudon, Ultra Necrozma and the three specific Tatsugiri Mega forms. These label/granularity differences are recorded rather than automatically reported as missing forms or patched into API data.

## Code and checks

- `examples/audit_pokeapi.rs`: cached complete metadata traversal and relationship/type/name/key/image-field audit. Contains a focused regression test for relative descriptive keys, common Mega filters, Magearna's reserved-name case and mismatched/empty identity prefixes.
- `examples/audit_pokeapi_images.rs`: bounded candidate fetch and complete PNG/checksum/transparency validation with cached response bytes/status/timestamps and per-tier failure records. The evaluation order is official-artwork, HOME, then form sprite; all twenty samples passed the first tier. This is evaluation tooling, not an adopted runtime fallback policy.
- No provider dependency, production module, CLI command, storage schema or source-selection contract was changed by this evaluation. No review or commit was made.
- Passed: `cargo fmt --check`; `cargo test --locked` (the existing 14 tests); `cargo test --locked --example audit_pokeapi` (one new key regression test); `cargo clippy --locked --all-targets -- -D warnings`; `git diff --check`; complete offline metadata replay; 20 actual PNG checks. One initial Clippy `is_multiple_of` finding was fixed and the required check rerun successfully. Existing btls native linker search-path warnings remain visible; executables link successfully on this macOS host.
- Reproduce metadata with `cargo run --locked --example audit_pokeapi -- /private/tmp/pokington-pokeapi`; append `--offline` to prohibit missing-resource fetches. Reproduce the existing sample image checks with `cargo run --locked --example audit_pokeapi_images -- /private/tmp/pokington-pokeapi/samples.json /private/tmp/pokington-pokeapi/images`. Cached bodies are reused. Do not pass the full form audit to the image runner unless a broader asset check is intended.

S01.T01 remains incomplete. The user still needs the source choice and, if retaining PokéAPI as a candidate, a clear canonical-form/image-gap policy. The evidence supports metadata feasibility and the sampled artwork, not a claim that PokéAPI currently satisfies every need.
